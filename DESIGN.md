# Bulls and Cows — дизайн проекта

Документ фиксирует правила, принятые решения и архитектуру. Разделы об алгоритмах,
сложности и принципах чистого кода добавляются по мере реализации.

## 1. Правила игры

Компьютер загадывает секрет — строку из `length` уникальных цифр в системе счисления `base`.
Игрок вводит попытки. После каждой попытки показывается результат:

- **bulls** — цифра есть в секрете и стоит на своём месте;
- **cows** — цифра есть в секрете, но стоит на другом месте.

Игра заканчивается, когда `bulls === length`. Лимита попыток нет; количество попыток и время
с начала раунда попадают в таблицу рекордов.

| base | Алфавит          | Доступные длины |
| ---- | ---------------- | --------------- |
| 2    | `0`–`1`          | 2               |
| 8    | `0`–`7`          | 2–6             |
| 10   | `0`–`9`          | 2–6             |
| 16   | `0`–`9`, `a`–`f` | 2–6             |

Секрет может начинаться с нуля: `0123` — корректный секрет длины 4 в десятичной системе.
Цифры в секрете и в попытке не повторяются. Для hex регистр не важен: `A` и `a` — одна цифра,
канонической формой считается нижний регистр.

## 2. Принятые решения

| Вопрос                | Решение                                                                  |
| --------------------- | ------------------------------------------------------------------------ |
| Повторная попытка     | В историю не добавляется и не засчитывается; показывается сообщение      |
| Топ-N                 | 10                                                                       |
| Формат рекорда        | `{ attempts, timeMs, date, length, base }`                               |
| Тай-брейк             | Попытки ↑, затем время ↑, затем дата ↑                                   |
| Reload посреди раунда | Раунд не сохраняется, возврат к экрану настроек                          |
| Секрет после победы   | Показывается в результате                                                |
| Таблица рекордов      | Один общий список; у каждой записи бейдж `length/base`                   |
| Длина                 | 2–6; для `bin` доступна только 2                                         |
| Ввод                  | Кнопка «Проверить» и Enter; недопустимые символы блокируются при вводе   |
| Язык                  | `en` по умолчанию, переключение на `ru`; выбор хранится в `localStorage` |
| История               | Хранится в порядке добавления, отображается новыми сверху                |
| Настройки             | Блокируются после старта раунда                                          |

### Ключи localStorage

| Ключ                        | Содержимое      |
| --------------------------- | --------------- |
| `bulls-and-cows:records:v1` | Массив рекордов |
| `bulls-and-cows:lang`       | `en` или `ru`   |

Версия в ключе рекордов позволяет менять формат без падения на старых данных.

## 3. Архитектура

### Слои

- `core` — чистые функции: генерация, валидация, сравнение, подсчёт, обновление состояния,
  ранжирование рекордов. Не импортирует DOM, `localStorage` и `ui`.
- `storage` — тонкий адаптер над интерфейсом `Storage` (`getItem`/`setItem`). В тестах
  подменяется фейком, в приложении используется `localStorage`.
- `i18n` — словари `en`/`ru` и функция перевода.
- `ui` — создание DOM через `createElement`/`textContent`, обработка событий, таймер.

Правило зависимостей: `ui → core`, `ui → i18n`, `ui → storage`. Обратных зависимостей нет.

## 4. Структуры данных

```ts
type Base = 2 | 8 | 10 | 16;

interface Settings {
  readonly length: number;
  readonly base: Base;
}

interface GuessEntry {
  readonly guess: string;
  readonly bulls: number;
  readonly cows: number;
  readonly at: number;
}

interface GameState {
  readonly settings: Settings;
  readonly secret: string;
  readonly history: readonly GuessEntry[];
  readonly startedAt: number;
  readonly finishedAt: number | null;
}

interface Record {
  readonly attempts: number;
  readonly timeMs: number;
  readonly date: string;
  readonly length: number;
  readonly base: Base;
}
```

Почему так:

- секрет — строка, а не число: сохраняет лидирующие нули и позволяет работать с hex;
- история — массив, пополняется через `[...history, entry]`, поэтому обновление состояния
  иммутабельно; количество попыток равно `history.length`, отдельный счётчик не нужен;
- время хранится как метки `Date.now()`, а не как счётчик тиков таймера: переживает
  сворачивание вкладки и не зависит от дрейфа `setInterval`.

## 5. Ограничения

- `body` в `index.html` пустой, кроме `<script type="module">`;
- динамическая разметка создаётся через `createElement`/`textContent`, `innerHTML` не используется;
- игровая логика — без классов;
- сторонние библиотеки для логики не используются;
- `localStorage` доступен только через адаптер `storage.ts`.
