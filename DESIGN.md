# Bulls and Cows — дизайн проекта

Документ описывает правила, принятые решения, архитектуру, структуры данных,
алгоритмы, сложность и принципы чистого кода, применённые в проекте.

## 1. Правила игры

Компьютер загадывает секрет — строку из `length` уникальных цифр в системе счисления `base`.
Игрок вводит попытки. После каждой попытки показывается результат:

- **bulls** — цифра есть в секрете и стоит на своём месте;
- **cows** — цифра есть в секрете, но стоит на другом месте.

Игра заканчивается, когда `bulls === length`. Лимита попыток нет; количество попыток и время
с начала раунда попадают в таблицу рекордов.

| base | Алфавит          | Доступные длины |
| ---- | ---------------- | --------------- |
| 2    | `0`–`1`          | 2               |
| 8    | `0`–`7`          | 2–6             |
| 10   | `0`–`9`          | 2–6             |
| 16   | `0`–`9`, `a`–`f` | 2–6             |

Секрет может начинаться с нуля: `0123` — корректный секрет длины 4 в десятичной системе.
Цифры в секрете и в попытке не повторяются. Для hex регистр не важен: `A` и `a` — одна цифра,
канонической формой считается нижний регистр.

## 2. Принятые решения

| Вопрос                | Решение                                                                   |
| --------------------- | ------------------------------------------------------------------------- |
| Повторная попытка     | В историю не добавляется и не засчитывается; показывается сообщение       |
| Топ-N                 | 10                                                                        |
| Формат рекорда        | `{ attempts, timeMs, date, length, base }`                                |
| Тай-брейк             | Попытки ↑, затем время ↑, затем дата ↑                                    |
| Reload посреди раунда | Раунд не сохраняется, возврат к экрану настроек                           |
| Секрет после победы   | Показывается в результате                                                 |
| Таблица рекордов      | Один общий список; у каждой записи бейдж `length/base`                    |
| Длина                 | 2–6; для `bin` доступна только 2                                          |
| Ввод                  | Кнопка «Проверить» и Enter; недопустимые символы блокируются при вводе    |
| Язык                  | `en` по умолчанию, переключение на `ru`; выбор хранится в `localStorage`  |
| История               | Хранится в порядке добавления, отображается новыми сверху                 |
| Настройки             | Блокируются после старта раунда                                           |
| Выход из раунда       | Кнопка в шапке; раунд прерывается, рекорд не сохраняется, секрет не виден |

### Ключи localStorage

| Ключ                        | Содержимое      |
| --------------------------- | --------------- |
| `bulls-and-cows:records:v1` | Массив рекордов |
| `bulls-and-cows:lang`       | `en` или `ru`   |

Версия в ключе рекордов позволяет менять формат без падения на старых данных.

## 3. Архитектура

### Слои

- `core` — чистые функции: генерация, валидация, сравнение, подсчёт, обновление состояния,
  ранжирование рекордов. Не импортирует DOM, `localStorage` и `ui`.
- `storage` — тонкий адаптер над интерфейсом `Storage` (`getItem`/`setItem`). В тестах
  подменяется фейком, в приложении используется `localStorage`.
- `i18n` — словари `en`/`ru`, функция перевода и хранение выбранного языка.
- `ui` — создание DOM через `createElement`/`textContent`, обработка событий, таймер.

Правило зависимостей: `ui → core`, `ui → i18n`, `ui → storage`. Обратных зависимостей нет.

## 4. Структуры данных

```ts
type Base = 2 | 8 | 10 | 16;

interface Settings {
  readonly length: number;
  readonly base: Base;
}

interface GuessEntry {
  readonly guess: string;
  readonly bulls: number;
  readonly cows: number;
  readonly at: number;
}

interface GameState {
  readonly settings: Settings;
  readonly secret: string;
  readonly history: readonly GuessEntry[];
  readonly startedAt: number;
  readonly finishedAt: number | null;
}

interface RecordEntry {
  readonly attempts: number;
  readonly timeMs: number;
  readonly date: string;
  readonly length: number;
  readonly base: Base;
}
```

Почему так:

- секрет — строка, а не число: сохраняет лидирующие нули и позволяет работать с hex;
- история — массив, пополняется через `[...history, entry]`, поэтому обновление состояния
  иммутабельно; количество попыток равно `history.length`, отдельный счётчик не нужен;
- время хранится как метки `Date.now()`, а не как счётчик тиков таймера: переживает
  сворачивание вкладки и не зависит от дрейфа `setInterval`;
- рекорд — плоский объект с явными `length` и `base`: таблица общая, а настройки видны
  в каждой строке;
- все поля помечены `readonly`: случайная мутация ловится компилятором.

### История попыток

История — неизменяемый массив `GuessEntry`. Новая попытка создаёт новый массив
(`[...history, entry]`), старые записи не меняются и не удаляются. На экране история
отображается в обратном порядке — новые сверху. Повторная попытка в историю не попадает:
`applyGuess` возвращает тот же объект состояния.

### Таблица рекордов

Таблица — массив не длиннее `MAX_RECORDS = 10`, отсортированный по правилам тай-брейка.
Вставка нового результата — это конкатенация и повторная сортировка с обрезкой до 10.
В `localStorage` массив хранится как JSON под версионированным ключом.

## 5. Алгоритмы

### 5.1. `createDigitValidator(base)`

Каррированная фабрика: первый вызов фиксирует систему счисления, второй проверяет один символ.

1. Алфавит системы берётся из `DIGITS[base]` — строки `01`, `01234567`, `0123456789`
   или `0123456789abcdef`.
2. Символ приводится к нижнему регистру, поэтому `A` и `a` равнозначны.
3. Проверяется, что длина строки равна 1 и что символ входит в алфавит.

Возвращённый предикат используется в двух местах: в `isValidGuess` и в фильтрации ввода
на экране игры (`ui/app.ts`).

### 5.2. `isValidGuess(guess, length, base)`

1. Строка приводится к нижнему регистру и разбивается на массив символов.
2. Проверяется точная длина.
3. `every` с предикатом из `createDigitValidator` проверяет каждый символ.
4. `new Set(digits).size === digits.length` проверяет отсутствие повторов.

Проверки объединены через `&&` и выполняются слева направо, поэтому при несовпадении длины
дорогие шаги не выполняются.

### 5.3. `evaluateGuess(secret, guess)`

1. Обе строки приводятся к нижнему регистру и разбиваются на массивы символов.
2. `bulls` — `filter` по позициям, где символы совпали, затем `length`.
3. `cows` — `filter` по позициям, где символ не совпал, но присутствует в секрете
   (`includes`), затем `length`.
4. Возвращается объект `{ bulls, cows }`.

Условие `digit !== secretDigits[index]` не даёт посчитать bull ещё и как cow. Алгоритм
опирается на предусловие «цифры не повторяются», которое гарантирует `isValidGuess`:
при повторах потребовалась бы мультимножественная логика с подсчётом вхождений.

Реализация сознательно использует два прохода `filter`, а не ручной цикл со счётчиками:
код читается как описание правила, а не как процедура.

### 5.4. `generateSecret(length, base, random)`

1. Проверяется, что `length` — целое число от 1 до размера алфавита; иначе `RangeError`.
2. Рекурсивная функция `pickDigits` выбирает цифры из пула:
   - индекс — `Math.floor(random() * pool.length)`;
   - выбранная цифра добавляется к результату;
   - пул пересобирается из частей до и после выбранной цифры, исходная строка не меняется;
   - рекурсия продолжается, пока не выбрано `length` цифр.
3. Источник случайности передаётся параметром (`random = Math.random`), поэтому в тестах
   поведение детерминировано: `() => 0` даёт `0123`, `() => 0.999999` — `9876`.

Удаление выбранной цифры из пула гарантирует уникальность без дополнительных проверок.

### 5.5. `countPossibleSecrets(length, base)`

Число секретов — это число размещений без повторений:

```text
P(b, n) = b * P(b - 1, n - 1)
P(b, 0) = 1
P(b, n) = 0, если n > b
```

1. Базовые случаи: пустой секрет — один вариант; длина больше алфавита — ноль вариантов.
2. Рекурсивный шаг: `base * countPossibleSecrets(length - 1, base - 1)`.
3. Функция обёрнута в `memoize`, поэтому каждый набор аргументов вычисляется один раз.
   Рекурсивные вызовы идут через уже мемоизированную функцию, то есть кэшируются все
   подзадачи, а не только верхний вызов.

Мемоизация нужна не ради алгоритма, а ради интерфейса: функция вызывается при каждом
открытии экрана настроек, чтобы показать «сколько всего возможно секретов».

### 5.6. Обновление состояния

`createGame(settings, secret, startedAt)` создаёт начальное состояние: копирует настройки,
приводит секрет к нижнему регистру, задаёт пустую историю и `finishedAt: null`.

`applyGuess(state, guess, at)`:

1. Если игра уже завершена или такая попытка была — возвращается **тот же** объект состояния.
   Это позволяет вызывающему коду отличить «принято» от «отклонено» сравнением ссылок.
2. Иначе вызывается `evaluateGuess`, создаётся запись `GuessEntry` с меткой времени.
3. История заменяется новым массивом, `finishedAt` выставляется в момент победы.

Функция чистая: время приходит параметром, исходное состояние не меняется.

### 5.7. Рекорды

- `compareRecords` задаёт порядок: попытки по возрастанию, затем время, затем дата.
  Даты хранятся в ISO, поэтому `localeCompare` сравнивает их хронологически.
- `sortRecords` копирует массив перед сортировкой — `Array.prototype.sort` мутирует.
- `takeTop` обрезает отсортированный список до `limit`.
- `addRecord` добавляет запись и оставляет лучшие `MAX_RECORDS`.
- `isRecordEntry` проверяет типы полей, допустимость `base` и валидность даты; используется
  при чтении `localStorage`, чтобы повреждённые данные не роняли приложение.

### 5.8. Хранение

`loadRecords(storage)`:

1. Читает строку по ключу; если ключа нет — пустой массив.
2. Разбирает JSON в `try/catch`; при ошибке — пустой массив.
3. Если значение не массив — пустой массив.
4. Иначе фильтрует элементы через `isRecordEntry`.

`saveRecords(storage, records)` сериализует массив в JSON и пишет по ключу.

Адаптер принимает любой объект с `getItem`/`setItem`, поэтому в тестах используется
хранилище на `Map`, а в браузере — `window.localStorage`.

## 6. Сложность

Обозначения: `n` — длина секрета (2–6), `b` — размер алфавита (2, 8, 10, 16),
`m` — число рекордов (не больше 10).

| Функция                | Время                                 | Память     | Обоснование                                                                                                   |
| ---------------------- | ------------------------------------- | ---------- | ------------------------------------------------------------------------------------------------------------- |
| `generateSecret`       | `O(n * b + n^2)`                      | `O(n * b)` | `n` выборов; на каждом шаге пул копируется за `O(b)`, а конкатенация строки результата даёт `O(n^2)` суммарно |
| `evaluateGuess`        | `O(n^2)`                              | `O(n)`     | два прохода `filter`, внутри каждого — `includes` по секрету длины `n`                                        |
| `isValidGuess`         | `O(n)`                                | `O(n)`     | проверка длины `O(1)`, `every` с валидатором `O(1)` на символ, `Set` за `O(n)`                                |
| `countPossibleSecrets` | `O(n)` первый вызов, `O(1)` повторный | `O(n)`     | `n` уровней рекурсии, каждый кэшируется; повторный вызов — поиск в `Map`                                      |

Пояснения:

- алфавит ограничен 16 символами, поэтому `b` — константа; для `generateSecret` основной
  вклад дают `n` выборов, а квадратичный член возникает из-за неизменяемых строк и при
  `n ≤ 6` практически не заметен;
- `evaluateGuess` можно сделать линейным через `Set`, но при `n ≤ 6` разница несущественна,
  а вариант с `filter` читается лучше и соответствует требованию использовать методы массивов;
- `countPossibleSecrets` без мемоизации был бы `O(n)` на каждый вызов; кэш превращает
  повторные вызовы в `O(1)`, что важно для перерисовки настроек;
- сортировка рекордов — `O(m log m)`, вставка — `O(m log m)` из-за повторной сортировки,
  при `m ≤ 10` это константа.

## 7. Принципы чистого кода

### Чистые функции и отсутствие побочных эффектов

Вся игровая логика в `src/core` — чистые функции: результат зависит только от аргументов.
Побочные эффекты изолированы в двух местах: `src/core/storage.ts` (запись в хранилище)
и `src/ui/app.ts` (DOM, таймер, `localStorage`). Поэтому `core` тестируется без браузера.

### Иммутабельность

`applyGuess` (`core/state.ts`) не меняет переданное состояние, а собирает новое через spread
и новый массив истории. `sortRecords` (`core/records.ts`) копирует массив перед `sort`.
Поля структур помечены `readonly`.

### Функции высшего порядка

`evaluateGuess` (`core/evaluate.ts`) построен на `filter` и `length`; `isValidGuess`
(`core/validate.ts`) — на `every`; `addRecord` и `sortRecords` — на `map`/`sort`/`slice`.
Ручных циклов со счётчиками в игровой логике нет.

### Каррирование

`createDigitValidator` (`core/digits.ts`) — фабрика, возвращающая предикат. Одна и та же
фабрика используется в валидации (`core/validate.ts`) и в фильтрации ввода (`ui/app.ts`),
то есть каррирование applied по делу, а не для демонстрации.

### Мемоизация

`memoize` (`core/memoize.ts`) — универсальная обёртка с кэшем в замыкании. Применена
к `countPossibleSecrets` (`core/count.ts`). Кэш недоступен снаружи, поэтому обёрнутая
функция остаётся чистой с точки зрения наблюдателя.

### Единственная ответственность

Каждый модуль отвечает за одно: `digits.ts` — алфавиты и валидатор, `secret.ts` — генерация,
`evaluate.ts` — сравнение, `state.ts` — состояние, `records.ts` — ранжирование,
`storage.ts` — сериализация, `i18n` — строки, `ui/app.ts` — экраны и события.

### Инъекция зависимостей

`generateSecret` принимает `random`, `createApp` — хранилище, `loadRecords`/`saveRecords` —
любой `StorageLike`. Это делает поведение детерминированным в тестах без подмены глобальных
объектов.

### Явные имена и константы

`MAX_RECORDS`, `RECORDS_KEY`, `LANGUAGE_KEY`, `BASE_LABELS`, `LENGTHS`, `BASES` —
вместо магических чисел и строк. Имена функций описывают результат (`isValidGuess`,
`countPossibleSecrets`), а не механику.

### Защитные проверки

`generateSecret` бросает `RangeError` на невозможные настройки; `isRecordEntry` отбрасывает
невалидные записи из `localStorage`; `applyGuess` игнорирует попытку после завершения игры.
Ошибка не «прячется», а обрабатывается в одном месте.

### Отсутствие `innerHTML`

`ui/dom.ts` создаёт элементы через `createElement`, текст добавляет через `append`.
Динамическая разметка нигде не собирается строками, поэтому XSS через пользовательский ввод
невозможен.

### Комментарии объясняют причину

JSDoc описывает контракт (`@param`, `@returns`, `@example`), а в неочевидных местах —
предусловия: например, в `evaluateGuess` указано, что цифры не повторяются, а в `memoize` —
что кэш у каждой обёртки свой.

### Тестируемость

151 тест в 10 наборах: каждая чистая функция покрыта отдельным набором, `random` и хранилище
подменяются, тесты не зависят друг от друга и не используют таймеры.

## 8. Ограничения

- `body` в `index.html` пустой, кроме `<script type="module">`;
- динамическая разметка создаётся через `createElement`/`textContent`, `innerHTML`
  не используется;
- игровая логика — без классов;
- сторонние библиотеки для логики не используются;
- `localStorage` доступен только через адаптер `storage.ts`.
